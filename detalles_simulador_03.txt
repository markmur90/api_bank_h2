Environment variables determine the external URLs. For example, .env.example defines where these routes live on the real server:

6  BASE_URL=https://example.com
7  TOKEN_PATH=/oidc/token
8  AUTHORIZE_PATH=/oidc/authorize
9  OTP_PATH=/otp/single
10  AUTH_PATH=/auth/challenges
11  API_PATH=/payments

Summary of the flow

    Obtain JWT
    POST {BASE_URL}/oidc/token (or /api/token) with username and password.
    Returns { "token": "..." }.

    Authorize the payment ID
    GET {BASE_URL}/oidc/authorize?payment_id=XYZ to mark the payment_id as authorized (simulated OAuth step).

    Request OTP challenge
    POST {BASE_URL}/auth/challenges (or /api/challenge) with JSON { "payment_id": "XYZ" } and header Authorization: Bearer <token>.
    Returns { "challenge_id": "...", "otp_required": true, "otp": "123456" }.

    Finalize transfer
    POST {BASE_URL}/otp/single (or /api/send-transfer) with JSON { "payment_id": "XYZ", "otp": "123456", "totp": "<code>" } and the same Authorization header.
    On success, you receive { "payment_id": "XYZ", "status": "PDNG" } (or final status after processing).

Alternatively, the whole process can be done via a single call to /payments or /api/transferencias/entrantes/, which performs OTP validation if an OTP is supplied; otherwise it returns the challenge so you can follow up with /otp/single.

These routes and the described flow ensure that an external transfer is correctly validated (token + OTP + TOTP) and then processed by TransferService.
